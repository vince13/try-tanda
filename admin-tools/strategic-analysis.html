1. Executive summary

Tanda is live on Google Play, release-ready for broad distribution, and completing final pre-open testing. The platform is not an idea-stage wedge: it is a full-stack short-form video + commerce system (Flutter client, Django API, wallets, payments, orders, affiliates/product tagging, analytics, and supporting services) built for emerging-market checkout, not just content.

Distribution is structurally different from a pure consumer growth playbook. Tanda has strategic MOUs with market unions across Nigeria — four in Abuja, four in Lagos, one in Enugu (negotiation ongoing), plus active discussions in other major markets. That is a B2B2C route to density (trusted aggregators, repeatable onboarding, localized trust) that generic “UGC bounty / 50k downloads” tactics do not reflect.

Fundraising framing: $500,000 for 10% implies a $5M pre-money headline for investor conversations (verify cap table and option pool with counsel before circulating).

Near-term north star: Open the app to the public with stable core journeys (install → feed → tag/shop → pay → fulfill → payout), union-coordinated rollout toward the April 2026 MVP rollout milestone, and investor-grade metrics that map to the real product surface area — not vanity download counts.

3. Holistic view of the system

Tanda’s moat is integration, not a single feature. Siloed tactics (e.g. raw download campaigns) only work if they plug into attribution, checkout, support, and union-led onboarding.

Attention layer Short-form video feed, creation, distribution hooks (including cross-platform publishing where implemented).
Commerce layer Product catalog, tagging on video, cart/checkout, orders, seller/affiliate flows.
Money layer Wallets, local payments, commissions/payouts, fraud and reconciliation discipline.
Trust layer Escrow/disputes, verification tiers, moderation — whatever is live must be operationally staffed (even lightly).
Growth layer Notifications, seeding/engagement tooling, analytics — closing the loop from marketing → activation → purchase → repeat.

4. Competitive landscape

Regional/specialized players (category-focused apps, live-shopping-first, reseller infrastructure, WhatsApp-first commerce) each win a slice. Tanda’s positioning: video + distributed discovery + local commerce infrastructure + creator/affiliate economics in one product, Africa-first. Fact-check competitor names and claims before external use.

5. Milestone map (detail)

Phased outcomes tied to product readiness, union GTM, and fundraising evidence. Timelines are relative to public open; calendar aligns to April 2026 MVP rollout.

Phase A — Public-open readiness (days–few weeks)

Goal: No embarrassing breakage on paths investors and unions will test.

  • Core journey QA: Cold install → signup → feed → product tag → cart → primary payment rail → order confirmation; creator/affiliate path if part of the union story.
  • Observability: Error budgets, crash-free sessions, payment success rate, API latency — definitions published internally.
  • Support & trust: Clear in-app path for failed payment / order issues; basic SLA with union liaisons (manual at first is OK).
  • Investor demo script: 5-minute path + 15-minute deep dive, same builds.

Fundraising effect: Removes “is it real?” diligence friction.

Phase B — Union-coordinated density (30–120 days, overlapping A)

Goal: Attributed growth and repeat behavior in a small number of geographies.

  • Union playbooks: One-pager per city — who activates sellers/creators, how testers become paid users, how disputes escalate.
  • Supply in lockstep: SME/creator onboarding matched to buyer campaigns so the feed does not feel empty.
  • Measurement: Union ID / campaign code / staff-assisted signup — honest and implementable — so CAC and activation are real.

Fundraising effect: Shows distribution beyond paid ads alone.

Phase C — Investor-grade metrics (continuous, report monthly)

Goal: Metrics that match stage (~1k pre-launch → post-open cohorts).

  • Activation: % completing first meaningful action within 24–72h; split pre-launch vs post-open.
  • Engagement: DAU/WAU/MAU, session length, retention D1/D7/D30 by cohort.
  • Commerce: GMV, orders, AOV, video-to-product tap, cart-to-paid, refund/chargeback proxy if available.
  • Creator economics: Active posters, GMV per active seller/affiliate, payout success and time-to-pay.
  • Trust: Dispute rate, CS response time, NPS or in-app thumbs where applicable.

Fundraising effect: Replaces vague traction with cohorts and conversion.

Phase D — Post-round scale (after $500k close — not day one)

Goal: Deploy capital against proven bottlenecks only.

  • Select hires (currently no new hire): e.g. ops/partnerships for unions, seller success, senior backend/payments after the queue is documented.
  • Logistics / cross-border: Only when domestic unit economics and SLAs are stable.
  • AI local languages: Align with support load and conversion data, not vanity roadmap.

Fundraising effect: Capital efficiency and credibility.

7. KPI appendix — staged targets

Lock numbers in your financial model; structurally:
